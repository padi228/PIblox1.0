# PIblox Cloud WebRTC synthetic demo

This is an isolated local WebRTC transport prototype. It streams an animated, server-generated test image to a browser. It does not capture a desktop, launch third-party applications, or receive remote keyboard/mouse input.

## Run

Use Python 3.10+ in a fresh virtual environment.

Windows:
    py -3 -m venv .venv
    .venv\Scripts\activate
    python -m pip install -r requirements.txt
    python webrtc_demo.py

Linux/macOS:
    python3 -m venv .venv
    source .venv/bin/activate
    python -m pip install -r requirements.txt
    python webrtc_demo.py

Open http://127.0.0.1:8790/ in a modern browser and select **Запустить WebRTC**. The service also exposes /health. The browser gathers local ICE candidates, posts an SDP offer to /offer, and receives the generated video track.

Stop the stream in the page to close the peer session. The server also closes failed peers and has a two-peer limit.

## Tests

Run the local API regression tests:

    python -m unittest discover -s tests -v

For a real headless-browser check, install Playwright and Chromium, then run:

    python -m pip install playwright
    python -m playwright install chromium
    python scripts/webrtc_browser_smoke.py

The browser smoke test starts a temporary local server, opens the page in Chromium, completes a real WebRTC offer/answer exchange, waits for decoded video frames, and confirms that stopping the stream releases the peer session.

GitHub Actions runs both API tests and the Chromium smoke test when files under services/piblox-cloud/ change. These checks validate the synthetic local transport only; they do not test desktop capture or any third-party app.

## Local-only boundary and limitations

- Uvicorn binds to 127.0.0.1:8790.
- HTTP routes reject non-loopback clients.
- The stream is synthetic video generated by the server; there is no desktop or app capture.
- No remote input, public hosting, authentication, TLS, TURN relay, or multi-user cloud isolation is provided.
- No third-party game compatibility is claimed.
- This is an experimental transport test, not a production cloud-gaming service.

Do not expose this prototype to the public internet. Any future remote service needs a separately reviewed authentication, authorization, TLS, resource-isolation, abuse-prevention, and cost-control design.
